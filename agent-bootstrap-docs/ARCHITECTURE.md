# ARCHITECTURE.md

## Stack
POSIX sh (dispatcher, lib, modules), Python 3 stdlib (manifest/checksum helper, simulator fixtures), Make, bats (tests), shellcheck/shfmt, containers for the test matrix. Runtime services installed by modules: LocalAI, llama.cpp rpc-server, Docker, Caddy/HAProxy, Prometheus/Grafana/Loki, Qdrant, Forgejo/Woodpecker, restic/borg, KVM/QEMU, etc.

## Core concepts
- **Node type** (`nodes/<TYPE>.conf`): ordered list of modules, allowed zones, conflicts, required RAM/disk.
- **Module** (`modules/<name>/`): one installable unit.
- **Zone**: Z0 OOB, Z1 cluster, Z2 services/agents, Z3 isolated lab.
- **Guardrails**: library of checks every module and agent step passes through.
- **State**: per-module records under `/var/lib/agent-bootstrap/`.

## Module contract
`module.conf` (shell-sourceable):
```
NAME=llamacpp-rpc
VERSION=<pinned>
DEPENDS="base init-service"
SHELL=sh
ARTIFACTS="name|url|sha256|size"   # one per line
ZONES="Z1"
NEEDS_ROOT=yes
MIN_RAM_MB=1024
MIN_DISK_MB=2000
```
Scripts:
- `install.sh` — idempotent; exit 0 ok, 10 skipped (already satisfied), others fail.
- `verify.sh` — read-only; exit 0 only if healthy.
- `uninstall.sh` — removes only what install created; never touches kernel/boot.
Environment passed in: `BS_NODE_TYPE BS_ZONE BS_INIT BS_MIRROR BS_OFFLINE BS_DRYRUN BS_CPU_FLAGS BS_STATE_DIR BS_LOG_DIR`.

## Data flow (apply)
```
CLI parse -> alias resolve -> load nodes/<TYPE>.conf -> doctor (preflight)
 -> guardrails (zone, conflicts, resources) -> resolve module DAG
 -> for each module: fetch_verified (mirror -> upstream) -> install -> verify -> state write
 -> summary + (optional) report to MONITORING_NODE
```
## Fleet data flow
```
BUILD_NODE --publishes--> MIRROR_NODE --serves--> all nodes (wizard installs)
CLUSTER_NODEs <--health-checked-- GATEWAY_NODE <--OpenAI API-- AGENT/ORCHESTRATION/VIBECODE nodes
all nodes --metrics/logs--> MONITORING_NODE ; configs/repos --> BACKUP_NODE
PROVISION_NODE --netboot/DHCP/DNS/time--> new machines ; OOB_NODE --> Z0 power/console
AGENT_NODEs --internet via--> EGRESS_NODE ; secrets <-- SECRETS_NODE
MALWARE/RANGE/(PENTEST in Z3) isolated: no route to Z1/Z2
```
## Network zones
| Zone | Purpose | Notes |
|---|---|---|
| Z0 | OOB/console | Air-gapped switch; only OOB_NODE |
| Z1 | Cluster | Cisco switches, cat5; inference traffic |
| Z2 | Services/agents | Gateway, monitoring, agents, mirror |
| Z3 | Isolated lab | Host-only/virtual; no uplink by default |

## Module boundaries
- Modules never edit other modules' files; cross-module config goes through `/etc/agent-bootstrap/conf.d/<module>.env`.
- `lib/` has no knowledge of specific modules.
- Node types contain no logic, only lists.
- Agent-written steps live in `templates/agent-steps/` and run only through `guardrails.sh`.

## Key dependencies
shellcheck, shfmt, bats, python3, make, curl or wget, sha256sum, tar, xz/zstd. Everything else per module.

## Simulator
`simulator/` renders from `simulator/fixtures/*.txt` generated by `tools/parity.py` from real command output (`usage`, `list`, `plan TYPE`). Simulator never executes anything.
